# Anti-Productivity Bubbles (APB) 仕様書

## 1. 目的

Windows デスクトップ上に複数のシャボン玉を重ねて表示し、各シャボン玉が画面下端の外から上端の外へ向かってゆっくり浮遊する表現を作る。シャボン玉の内側では背後のデスクトップ画面を屈折させ、輪郭のハイライトや薄膜の色変化によって透明な球体として見せる。

本書は実装済みの仕様を記録する（英語版: [SPECIFICATION.en.md](SPECIFICATION.en.md)）。実機で未検証の品質項目は「9. 要確認の項目」に記載する。

## 2. 動作環境と利用形態

- Windows 10/11（Windows Graphics Capture 対応環境）のデスクトップ上で動作するアプリケーション。
- 現在表示中のデスクトップをリアルタイムに背景として取り込み、その上にシャボン玉を合成する。
- 全モニターを対象とし、各モニターに専用のオーバーレイウィンドウを1枚ずつ表示する。各モニターは自身の画面内容だけを屈折の背景に使う。
- 通常時はデスクトップ操作を妨げないオーバーレイとする。

## 3. 機能要件

### 3.1 シャボン玉の表示と移動

- シャボン玉は画面下端より下から出現し、上方向へ移動して画面上端より上へ抜ける。
- 上端から抜けたシャボン玉は、画面下端より下のばらついた高さ・横位置・速度で再び出現する。これにより規則的な並びを避ける。
- 同時表示数は **1モニターにつき15個**（1台=15、2台=30、3台=45）を既定値とする。
- 直径は 250px ±50px（200〜300px）、上昇速度は 30〜60px/秒を既定値とする。値は個体ごとにランダムに決める。
- 起動時（設定の再読み込み時を含む）は、全個体を画面下端より下の外側に待機させ、時間差で下から上ってくるようにする。横位置は、画面を列×行のセルに分けて各個体をシャッフルしたセルに割り当て、セル内に小さな位置差を付けて分散する。待機の高さはセルの行に応じて画面1枚分の範囲にばらつかせる。列数は画面の縦横比と玉数から自動計算する（15個・16:9では5列×3行）。
- 左右の揺れは、振幅 24〜48px、角速度 0.35〜0.7rad/秒（個体ごとにランダム）の正弦波とする。位相は個体ごとに異なる。
- 目標フレームレートは60 FPS、上限は120 FPSとする。描画タイマー間隔は約16msである。

### 3.2 見た目

- 背景を隠す不透明な円ではなく、透明感のある球体として描画する。
- 輪郭に細い反射ハイライトを設け、玉の一部に小さな光源反射を置く。
- 輪郭や表面に薄膜由来の虹色を控えめに加え、写実寄りにする。
- 玉の内側の濃い塗り、全画面への色かぶり、強い後光を生じさせない。
- 玉同士が重なる場合も形状が判別でき、過度に明るくならないよう合成する。

### 3.3 背景の屈折

- 玉の内側で、取り込んだデスクトップ画像を局所的にサンプリングし直すことで屈折を表現する。
- 屈折量は `local * 半径 * 屈折強度 * sqrt(1 - r^2)` で与え、中心から輪郭に向かって滑らかに変化する。
- 屈折強度の既定値は 0.55 とする（初期値 0.18 から強化済み）。設定ファイルで 0〜3 に変更できる。
- 玉の外側の背景は変更しない。
- 画面端でのサンプリングは画面範囲内に制限し、反対側から画像が回り込まないようにする。
- オーバーレイ自身が背景キャプチャに映り込む自己フィードバックを `WDA_EXCLUDEFROMCAPTURE` で防ぐ。

### 3.4 操作と終了

- オーバーレイはフォーカスを奪わず、マウス操作は下のアプリケーションへ透過する。
- 既定の終了キーは Esc とする。低レベルキーボードフック（`WH_KEYBOARD_LL`）で検出するため、オーバーレイが非アクティブでも終了できる。
- 終了キーは設定ファイルで変更でき、`LShift+Esc` や `Ctrl+Alt+Q` のような同時押しも指定できる（3.5 参照）。
- 終了時は全モニターのオーバーレイを閉じる。
- 非常用の終了キーとして、`Esc` + `左Shift` + `左Ctrl` の同時押しを常に有効とする（`ExitKey` の設定に依存しない）。
- 二重起動を防ぐ（名前付きミューテックス）。2つ目の起動ではメッセージを表示して終了する。

### 3.5 設定ファイル

実行ファイルと同じフォルダの `settings.ini`（INI 形式）で設定する。ファイルが無い、項目が欠けている場合は既定値を使う。値が不正な場合も既定値を使い、警告を表示してログに記録する（3.8 参照）。

- 起動時に読み込み、実行中も約1秒間隔で更新日時を監視し、変更を検出すると自動で再読み込みして全モニターのオーバーレイを再構築する（玉の配置は初期状態に戻る）。タスクトレイメニューからも再読み込みできる。
- INI のコメントは行頭の `;` のみ（値の後ろへのコメントは不可）。

| セクション | キー | 既定値 | 有効範囲・備考 |
|---|---|---|---|
| Bubbles | Count | 15 | 1〜64（1モニターあたり） |
| Bubbles | DiameterMin / DiameterMax | 200 / 300 | px。下限10 |
| Bubbles | SpeedMin / SpeedMax | 30 / 60 | px/秒。下限0 |
| Sway | AmplitudeMin / AmplitudeMax | 24 / 48 | px。下限0 |
| Sway | RateMin / RateMax | 0.35 / 0.7 | rad/秒。下限0 |
| Refraction | Strength | 0.55 | 0〜3 |
| Input | ExitKey | Esc | 下記参照 |
| Power | OnBattery | Normal | `Normal` / `Reduce` / `Pause`（3.7 参照） |
| Power | BatteryFps | 30 | 5〜60。`Reduce` 時のフレームレート |
| Monitor*n* | Enabled | 1 | 0 でそのモニターには表示しない |
| Monitor*n* | Count | （Bubbles/Count） | そのモニターの玉の数（1〜64）。全モニター無効の場合は警告して全モニターに表示する |

- Min と Max が逆の場合は自動で入れ替える。
- `ExitKey` はキー名（`Esc`, `Q`, `F12`, `Space`, `Enter`, `Pause` など）または `0x1B` のような16進仮想キーコードで指定する。
- `+` で連結すると同時押しになる。最後のキーが終了のトリガーで、それ以前のキーは押下中である必要がある。
  - 修飾キー名: `Shift`/`LShift`/`RShift`、`Ctrl`/`LCtrl`/`RCtrl`、`Alt`/`LAlt`/`RAlt`、`Win`/`LWin`/`RWin`。
  - 解釈できないキー名を含む場合は既定の Esc を使う。
- `Monitor<n>` の n は Windows が表示するディスプレイ番号（デバイス名 `\\.\DISPLAYn` の n）。
- ビルド時に `settings.ini` は出力フォルダへコピーされる（ソース側が新しい場合のみ）。

### 3.6 タスクトレイ

通知領域にアイコンを表示し、クリックでメニューを開く。項目: 一時停止/再開、設定を再読み込み、設定ファイルを開く、Windows 起動時に実行（`HKCU\...\Run` の登録/解除）、終了。メニューの表示言語は OS の UI 言語（日本語/それ以外は英語）に従う。

### 3.7 省電力

`OnBattery` が `Reduce` の場合、バッテリー駆動中は描画を `BatteryFps` に間引く。`Pause` の場合、バッテリー駆動中はオーバーレイを非表示にして描画を止める。AC 電源に戻ると自動で復帰する。電源状態は約1秒ごとに確認する。この機能はシェーダーの描画内容には影響しない。

### 3.8 エラー通知とログ

- 設定値が不正な場合、起動時はメッセージボックス、実行中の再読み込み時はトレイの通知で項目を知らせ、その項目は既定値で動作する。
- 動作ログを `%LOCALAPPDATA%\APB\APB.log` に書く（起動ごとに上書き）。内容は起動・モニター構成・設定の警告・エラーのみで、画面内容は記録しない。

### 3.9 ディスプレイ構成の変更

`WM_DISPLAYCHANGE` を受けると、約1秒待ってから全モニターのオーバーレイとキャプチャを再構築する。失敗した場合は最大3回、1.5秒間隔で再試行し、なお失敗すればエラーを表示して終了する。

## 4. 実装方針

- C++17 / Win32、Direct3D 11、HLSL Shader Model 5.0。MSVC v143、Windows SDK 10.0.26100.0。
- シェーダーはビルド時に fxc でコンパイルし、ヘッダー（バイトコード配列）として exe に埋め込む。C++ ランタイムは静的リンク（`/MT`）とし、配布先に追加のランタイムを要求しない。
- 描画タイマーと通知領域アイコン、メッセージ処理は、非表示のコントロールウィンドウが担当する。オーバーレイウィンドウはモニターの再構築で破棄・再作成される。
- Windows Graphics Capture（`CreateForMonitor`）でモニターごとにデスクトップを取得し、ピクセルシェーダーで背景の再サンプリングとシャボン玉の合成を行う。
- D3D11 デバイス、シェーダー、サンプラー、ブレンド、ラスタライザー、定数バッファは全モニターで共有する。レンダーターゲット、ステージングテクスチャ、DIB はモニターごとに持つ。
- 玉はインスタンス描画（`DrawInstanced(6, 個数)`）で描く。シェーダー定数バッファの玉配列は最大64個で固定し、実際の個数は設定値で決める。
- 描画結果は STAGING テクスチャ経由で CPU に読み戻し、DIB に書いて `UpdateLayeredWindow`（ULW_ALPHA、プリマルチプライドアルファ）で表示する。
- ウィンドウ属性は `WS_EX_LAYERED | TOPMOST | NOACTIVATE | TRANSPARENT | TOOLWINDOW`。
- プロセスは Per-Monitor DPI Aware V2 とし、各モニターの物理ピクセル単位で描画する。
- 1つのタイマーで全モニターを順に更新・描画する。経過時間の1フレーム上限は0.1秒。
- D3D11 のバックフェイスカリングで玉が消えないよう、`D3D11_CULL_NONE` を使う。

## 6. 性能・品質の受け入れ条件

- デスクトップを継続的に表示しながら、シャボン玉が下から上へ途切れず移動する。
- 一部が画面外にある玉が不自然に端で切れず、出現・退出が確認できる。
- 玉の内部で背景が明確に歪み、外側には意図しない歪みがない。
- 自己フィードバック、色かぶり、著しいちらつきがない。
- マウス操作と通常のキーボード操作が下のアプリケーションで継続できる。
- 1モニターにつき15個の玉を表示した状態で、目標60 FPSで動作することを目指す。モニター数に応じて CPU 読み戻し負荷が増える。

## 7. 対象外（現バージョン）

- 設定画面などの GUI。設定はファイル編集のみ。
- モニターごとの玉の数・有効/無効以外の個別設定、複数モニターをまたぐ玉。
- インストーラー。
- 全画面アプリの検出による自動非表示。
- 物理シミュレーション、玉同士の衝突、風やユーザー操作による反応。
- コード署名。ARM64 と古い Windows への対応（動作確認は Windows 11 x64 のみ）。

## 9. 要確認の項目

- 3台以上のモニター構成での FPS と CPU/GPU 負荷（CPU 読み戻しを伴うため、60 FPS は目標であり未保証）。
- 高解像度・高リフレッシュレートのモニターでの動作。
- 玉数を大きくした場合（最大64個）の負荷。
- 全画面アプリ（ゲーム、動画の排他的全画面）上での表示と、終了キーの動作。
- 管理者権限で動作しているアプリが前面にある場合のキー検出。
